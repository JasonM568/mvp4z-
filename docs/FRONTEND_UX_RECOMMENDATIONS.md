# 巽風系統前端視覺設計與瀏覽動線建議書

版本：1.0  
日期：2026-08-10  
範圍：公開網站、四象問天機、面相系統、會員中心與管理後台

---

## 一、執行摘要

巽風目前已有三種不同性質的服務：

1. 四象問天機：會員使用的四術合參決策產品。
2. 巽風面相系統：照片品質檢查與民俗文化觀察產品。
3. 風羿老師專業服務：預約、企業顧問、現場堪輿與課程。

現況的主要問題不是功能不足，而是三種服務仍共用一套偏傳統企業官網的導覽方式。首頁雖已將「四象問天機」放入主視覺，使用者仍可能不確定巽風首先是老師品牌、易學工具平台，還是顧問公司；登入後也缺少集中管理點數、未完成任務與歷史報告的工作台。

建議將前端重整成「一個品牌、兩套數位系統、一個真人服務出口」：

- 巽風品牌
  - 四象問天機
  - 巽風面相
  - 風羿老師專業諮詢

第一階段先處理導覽分流、首頁資訊層級與會員工作台；第二階段統一報告視覺、歷史紀錄與手機互動；第三階段補上數據追蹤及轉換優化。

## 二、現況盤點

### 2.1 已具備的優點

- 首頁已有「四象問天機」東方玄學主視覺，主名稱、四術元素與主按鈕清楚。
- 首頁已同時露出四象、面相與老師諮詢三個入口。
- 四象已有 Landing → Input → Scanning → Report 的完整流程。
- 面相已有 Landing → Capture → Quality Check → Report 的明確步驟。
- 面相照片有隱私、同意、品質檢查與扣點邊界提示。
- 四象與面相皆有會員驗證及點數規則，不是只有視覺入口。
- 後台已有四象紀錄、報告設定、排盤流派、老師文件、面相知識庫與模型認證。

### 2.2 主要問題

| 問題 | 現況 | 使用者影響 | 優先級 |
|---|---|---|---|
| 主導覽過密 | 同時放入關於、服務、企業、案例、課程、預約、四象、AI、面相、方案、會員 | 難以快速辨識核心入口，手機更容易擁擠 | P0 |
| 品牌層級混合 | 首頁先講四象，後段又切回堪輿品牌、企業服務與 CMS 服務目錄 | 首頁缺少單一清楚主題 | P0 |
| 會員中心不是工作台 | 主要顯示方案與「進入 AI 會員版」 | 四象、面相、紀錄與點數沒有一站式入口 | P0 |
| 產品命名仍有舊語彙 | 周邊介面仍可能出現 AI 會員版、易學決策等稱呼 | 品牌記憶不一致 | P1 |
| 四象流程缺少持續狀態 | 長時間生成主要依靠單頁狀態 | 重新整理或離開後不易找回進度 | P1 |
| 面相歷史入口不明顯 | 已有歷史頁，但主要流程缺少醒目入口 | 回訪者不易找到舊報告 | P1 |
| 視覺系統尚未完全統一 | 公開頁、會員頁、四象、面相與後台使用不同元件語言 | 看起來像多個系統拼接 | P1 |
| 後台功能平鋪 | 所有功能列成單層長選單 | 老師難以按任務找到功能 | P1 |

## 三、建議資訊架構

### 3.1 公開網站主導覽

桌機主導覽縮減為六個主項：

1. 四象問天機
2. 面相系統
3. 老師服務
4. 案例與課程
5. 會員方案
6. 登入／會員中心

「老師服務」下拉包含專業服務、企業顧問、預約諮詢與關於風羿老師；「案例與課程」下拉包含案例實績與課程講座。

手機版使用右上角選單，底部只固定一個依頁面變化的主按鈕：

- 首頁：開始問天機
- 四象頁：生成天機書
- 面相頁：開始品質檢查
- 服務頁：預約老師

### 3.2 會員工作台

將現有會員中心改為「我的巽風」：

- 點數與方案摘要
- 繼續進行
  - 未完成的四象問事
  - 已通過品質檢查的面相任務
- 快速開始
  - 開始問天機
  - 開始面相觀察
  - AI 即時問答
- 我的報告
  - 四象天機書
  - 面相觀察報告
- 帳號、方案與點數紀錄

會員登入後，主導覽不應再額外展開多個 AI 連結，而應只顯示「我的巽風」，進入後再按任務分流。

### 3.3 管理後台

後台建議分組：

- 營運總覽：總覽、會員、訂單、發票、Token 用量
- 四象問天機：天機書紀錄、報告內容、排盤流派、老師文件
- 面相系統：分析紀錄、面相知識庫、OpenAI 照片認證
- 顧問服務：預約名單

老師登入後的首頁應優先顯示待辦：

- OpenAI 照片認證是否有效
- 待審核或待發布的面相知識
- 最近失敗的分析任務
- 新預約與待處理訂單
- 本週四象與面相使用量

## 四、首頁視覺與內容

### 4.1 首屏層級

目前東方玄學方向正確，建議保留深墨底色、玄金主色、朱砂印記、羅盤與八卦方位，以及宋體類標題。

首屏資訊順序固定為：

1. 品牌識別：巽風／風羿老師
2. 主名稱：四象問天機
3. 副標：命・局・卦・象，四術合參・一事定向
4. 不超過 60 字的價值說明
5. 唯一主要按鈕：開始問天機
6. 次要文字連結：先了解如何運作

面相與企業顧問不應和「開始問天機」使用相同視覺權重，應放在首屏下方的三大入口卡。

### 4.2 首頁段落順序

1. 四象問天機主視覺
2. 三大入口：四象／面相／老師諮詢
3. 四象如何合參：命、局、卦、象
4. 最終會得到什麼：《巽風四象天機書》示意
5. 適合詢問的題型：事業、合作、選擇、時機、風險
6. 信任區：老師經歷、方法邊界、隱私與扣點原則
7. 面相系統介紹
8. 真人服務與案例
9. 會員方案
10. Footer

目前「風羿老師」與「服務項目」可保留，但應移到產品介紹之後，避免使用者剛理解四象就被帶回傳統官網。

### 4.3 色彩規範

| 用途 | 建議色 | 說明 |
|---|---|---|
| 主背景 | #07110F | 深墨綠，承接現有品牌 |
| 次背景 | #0E1A16 | 卡片與區塊層次 |
| 主金 | #D8B15F | CTA、標題、羅盤線條 |
| 淺金 | #F1D58F | 高亮文字 |
| 朱砂 | #B4533A | 印章、警示與文化符號 |
| 玉綠 | #6EE7B7 | 成功狀態，不作主要品牌色 |
| 主文字 | #F5F0E6 | 高對比正文 |
| 次文字 | #BDB5A8 | 說明文字 |

原則：

- 金色只用於最重要的行動與核心標題。
- 綠色只用於成功、通過、已完成等系統狀態。
- 朱砂只用於印記、警示與需注意內容。
- 同一畫面最多一個實心金色主按鈕。

### 4.4 字體與元件

- 品牌標題：Noto Serif TC 或宋體類。
- 功能介面：Noto Sans TC。
- 正文最小 16px；手機說明文字不低於 14px。
- 正文行高 1.7–1.9；每行中文字控制在 28–36 字。
- 避免大量英文全大寫標籤；中文必須是主要資訊。
- 按鈕高度 48–52px，點擊區域不小於 44×44px。
- 核取方塊與單選 18–20px，文字使用剩餘寬度自然換行。
- 品牌卡用 4px／32px 對角，工具卡統一 16px。
- 所有 loading、error、empty state 使用一致組件。

## 五、四象問天機動線

### 5.1 主流程

首頁 → 四象介紹 → 登入／確認方案 → 輸入問題 → 補充資料 → 確認扣點 → 四象合參進度 → 巽風四象天機書 → 儲存／下載／再次問事／預約老師

### 5.2 Landing

保留單一主 CTA「開始問天機」，補充三項資訊：

- 適合問什麼：一次聚焦一件具體事情。
- 需要準備什麼：問題、出生資料；進階資料可選填。
- 會得到什麼：四象合參摘要、行動方向、風險與停損條件。

訪客按下 CTA 後才導登入；登入完成必須回到原流程。

### 5.3 Input

表單拆成兩層：

- 必要資料：問題、出生年月日時間、性別。
- 提高準確度：奇門、六爻、梅花與案件細節；預設收合。

送出前加入摘要確認：問題全文、啟用術數、本次扣點、預估時間與生成後即扣點規則。

### 5.4 Scanning

約兩分鐘等待是高流失點，建議：

- 顯示真實階段：排命、定局、成卦、取象、四象合參。
- 明確說明是否可以離開。
- 以 run id 保存狀態，重新整理後可恢復進度。
- 超時改顯示「仍在整理天機書」，不要停在 99%。
- 完成時提供站內通知或 Email。

### 5.5 Report

第一屏只回答：

1. 建議：可進／可試行／暫緩／不建議／補資料。
2. 四象共識：四術是否同向。
3. 下一步：現在最該做的三件事。

行動按鈕排序：

1. 儲存到我的報告
2. 下載 PDF
3. 預約老師覆核
4. 再問一件事
5. Markdown／JSON 收進「更多下載」

## 六、面相系統動線

### 6.1 主流程

首頁／我的巽風 → 面相介紹 → 選擇自己或他人 → 拍照規範 → 拍攝／上傳 → 同意處理 → 免費品質檢查 → 品質結果 → 確認 20 點 → 報告 → 刪除照片／查看歷史／預約老師

### 6.2 Landing

在現有三項信任說明之外增加：

- 合格與不合格照片圖例。
- 具體照片刪除時間，不只寫「依政策」。
- 「完整報告 20 點；品質檢查免費」。
- 「我的面相報告」入口。

### 6.3 Capture

- 選擇他人後，立即解釋取得同意的原因。
- 照片預覽下方顯示檔案大小、格式與 EXIF 處理狀態。
- 核取方塊固定 18–20px，長文字自然換行。
- 相機與選擇照片視覺同級，但只保留一個主要色。
- 品質失敗直接提供改善動作，例如「請移到正面光源」。

### 6.4 Quality Result

用四張狀態卡顯示人臉、清晰度、光線與角度。若通過，主按鈕顯示「生成面相觀察報告・20 點」；若未通過，主按鈕改成「重新拍攝」，避免競爭動作。

### 6.5 Report

- 摘要與完整報告分層。
- 清楚顯示民俗文化參考邊界。
- 提供「立即刪除原始照片」與刪除狀態。
- 提供下載 PDF、儲存報告、開始新分析與歷史入口。
- confidence 較低時使用「觀察有限」，不要用模糊百分比。

## 七、跨系統一致性

### 7.1 對外命名

| 類型 | 固定名稱 |
|---|---|
| 主產品 | 四象問天機 |
| 副標 | 命、局、卦、象，四術合參，一事定向。 |
| 報告 | 巽風四象天機書 |
| 核心章節 | 四象合參 |
| 面相產品 | 巽風面相系統 |
| 面相報告 | 巽風面相文化觀察報告 |
| 會員入口 | 我的巽風 |

「AI 會員版」「易學決策報告」「順轉導航」只保留為歷史或內部技術名，不再出現在主要對外介面。

### 7.2 共用狀態

- 尚未開始
- 資料準備中
- 檢查中
- 分析中
- 報告整理中
- 已完成
- 需要補充資料
- 未通過／失敗

### 7.3 我的報告

- 可依四象／面相篩選。
- 顯示問題或報告名稱、日期、狀態與扣點。
- 提供查看、下載與刪除。
- 不保留永久面相照片縮圖，以抽象圖標與文字摘要表示。

## 八、響應式與無障礙

- 以 390px 為主要手機驗收尺寸，另補測 320px。
- 首頁羅盤不得造成水平捲動。
- 手機主按鈕使用全寬。
- 表單欄位字級至少 16px，避免 iOS 自動放大。
- 固定底部 CTA 保留 iPhone safe area。
- 長報告提供章節目錄與回到頂端。
- 所有文字與背景符合 WCAG AA 對比。
- 動畫遵循 prefers-reduced-motion。
- 不以顏色單獨代表吉凶、成功或失敗。
- 表單錯誤可被螢幕閱讀器讀取。
- 羅盤等裝飾設為 aria-hidden。

## 九、建議執行順序

### P0：導覽與轉換主線

預估 3–5 個工程日：

1. 重整桌機與手機主導覽。
2. 將會員中心改為「我的巽風」工作台。
3. 依產品決策順序重排首頁。
4. 四象與面相加入歷史報告入口。
5. 清理對外舊名稱。

驗收：

- 新訪客 5 秒內能說出兩套數位系統差異。
- 首頁首屏只有一個主要 CTA。
- 會員最多兩次點擊到達四象、面相或歷史報告。
- 手機 320px 無水平捲動。

### P1：統一產品體驗

預估 5–8 個工程日：

1. 建立共用按鈕、表單、狀態、卡片與提示元件。
2. 四象加入可恢復的 run 狀態。
3. 面相補上照片圖例、具體保存時間與刪圖入口。
4. 統一報告摘要、PDF 與歷史紀錄。
5. 後台選單分組並建立待辦首頁。

驗收：

- 四象生成中重新整理仍可恢復。
- 面相使用者知道照片何時刪除並可主動刪除。
- 主要表單錯誤都在欄位附近呈現。
- 四象與面相的 loading／error／complete 語言一致。

### P2：數據與優化

預估 3–5 個工程日：

1. 建立首頁到報告的轉換漏斗。
2. 記錄四象表單放棄點與面相品質失敗原因。
3. 增加完成通知。
4. 改善 SEO、分享圖與報告分享卡。
5. 依數據調整 CTA 與方案呈現。

追蹤指標：

- 首頁到四象及面相入口點擊率
- 登入完成率
- 四象表單完成率
- 四象報告成功率與等待時間
- 面相品質通過率
- 品質通過後的付費轉換率
- 報告下載率
- 報告後預約老師轉換率

## 十、不建議事項

- 不讓羅盤、粒子與光效同時大量動畫。
- 不在首頁同時放超過三個主要按鈕。
- 不再增加新的產品別名。
- 不讓「AI」成為前台主訴求；AI 是交付技術，不是品牌價值。
- 不把面相照片做成永久縮圖牆。
- 不讓 PDF、Markdown、JSON、分享與重試全部同等突出。
- 不用神化、保證結果或製造恐懼的文案推動轉換。
- 不因桌機畫面足夠寬，就把所有功能塞進主導覽。

---

## 十一、第一批可直接開工項目

1. 建立響應式 Header：六個主項、兩組下拉、手機抽屜。
2. 建立「我的巽風」：點數、快速開始、未完成任務、最近報告。
3. 重排首頁，新增「四象如何合參」與天機書交付示意。
4. 四象報告將下載收斂為 PDF 主按鈕與更多選單。
5. 面相 landing 加入歷史入口、報告費用與照片保存期限。
6. 面相報告加入刪除照片與查看歷史。
7. 後台導覽分成營運、四象、面相、顧問四組。
8. 建立共用 Design Tokens 與 UI 元件清單。

建議先完成第 1–3 項。這三項會直接改善新訪客與會員的主要瀏覽路徑，而且不需要改動四術演算法或面相分析核心。

## 十二、結論

巽風前端下一步不應只是繼續增加頁面，而是把已有能力整理成清楚的產品結構：

1. 先統一入口與會員工作台。
2. 再統一四象、面相的流程與報告。
3. 最後以真實轉換數據優化。

這條路線不需要改動四術演算法、扣點交易或面相核心資料庫，可將視覺與動線工程和既有核心工程分離，降低互相衝突的風險。
